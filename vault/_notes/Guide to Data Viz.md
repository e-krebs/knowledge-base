Sara Dholakia's framework for choosing the right chart type: ask four questions about message, purpose, audience, and data, then narrow the chart type down from there. Reach for it whenever you're picking a chart for a report or dashboard and want to justify the choice rather than default to a bar chart.

## how
Ask these four questions in order to narrow the chart choice:
- What message am I trying to communicate with the data? — match chart complexity to message complexity, e.g. a simple table for a single idea, a grouped bar graph when a comparison needs to come through.
- What is the purpose of the data visualization? — pick a chart from the family that answers comparison, composition, distribution, or relationship (some charts, like donut charts, answer more than one).
- Who is the audience? — favor familiar formats (e.g. a grouped bar graph) over unfamiliar ones (e.g. a radar chart) for a general audience; experts can handle less-familiar types.
- What type and size of data am I working with? — eliminate chart types that don't fit the data's type (quantitative/categorical/ordinal) or that don't scale to the data set's size (e.g. avoid bar graphs or pie charts with dozens of categories).

Label and annotate sparingly: add value labels only when they genuinely help (e.g. labeling totals on a stacked area graph saves the audience from doing math), and avoid labeling every element in a large data set — it overcrowds the chart and makes it harder to read.

## gotchas
- A chart type can answer more than one purpose at once (e.g. a donut chart covers both comparison and composition) — don't assume purpose maps 1:1 to chart type.
