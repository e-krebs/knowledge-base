`--erasableSyntaxOnly` is a TypeScript 5.8 compiler flag that turns enums, namespaces, and class parameter properties into errors, because none of them can be deleted from a file without changing its runtime behavior the way a type annotation can. Reach for it when a codebase — or Node's native TS support — needs every file to compile by simple type-stripping, with no separate transform step.

## how
Flags these constructs as errors:
```typescript
// Error! Not allowed
enum Example {
  foo,
}

// Error! Not allowed
namespace OhNo {
  export const foo = 1;
}

class X {
  // Error! Not allowed
  constructor(private foo: string) {}
}
```
"Erasable" means deleting the syntax leaves valid, behavior-preserving JavaScript — true of a type annotation:
```typescript
const foo: string = 'foo';
const foo         = 'foo';
```
but not of enums or namespaces, which bundlers must actually transform to remove.

Node's own TypeScript support already defaults to erasable-syntax-only, which the source gives as the motivation for the flag.

## gotchas
- The `paths` compiler option doesn't work under this flag; use Node's native `package.json#imports` for import aliases instead.
